# ITC 情感对照分析（一键运行版 v2）

本项目不会修改用户已有的结果文件。程序自动完成：识别数据 → 口径核验 → 四象限划分 → 1:1 匹配 → 统一模型预测 → Q11 与 Q10/Q01/Q00 直接比较 → Excel/JSON/PNG 输出。

## 操作（只运行一个脚本）

1. 用 PyCharm 打开 `ITC情感对照分析_一键运行版/`。
2. 在 PyCharm Terminal 安装依赖：`pip install -r requirements.txt`。`torch` 未锁定特殊版本，pip 会按当前环境选择；已有可用版本时不会要求改成特定版本。
3. 确认两个数据来源位于 `/Users/bytedance/Desktop/1013情感分析`：
   - ITC 文件优先使用 `隐形三角引用数据.xlsx`，也识别文件名含 `ITC/itc` 的数据文件；
   - 完整原始数据可以是一个文件，也可以是多个 Excel/CSV/CSV.gz/Parquet 分片。
4. 在 PyCharm 中右键 `一键运行_ITC对照分析.py`，选择“运行”。无需设置任何参数，也不要分别运行其他 Python 文件。

如果目录要变，只修改 `config.py` 顶部的 `DATA_DIR`。结果自动写入数据目录下的 `ITC对照分析结果/`。

## 自动识别与内存控制

程序扫描数据目录下的 CSV、CSV.gz、Parquet、XLSX，排除 ITC 文件、结果文件、隐藏文件和临时文件。其他 Excel 会先检查是否包含以下 16 列，schema 不符会在控制台说明并安全跳过，不会误当原始分片：

`文献A_WOSID、文献A题目、文献D1_WOSID、文献D1题目、Section1、Classification1、引用句1、文献D1参考文献、文献D2_WOSID、文献D2题目、Section2、Classification2、引用句2、文献D2参考文献、耦合强度、sbert相似度`

CSV、Parquet 和 XLSX 均按块读取。约 2,085,004 行的完整数据不会一次性载入内存。多个合格分片会自动合并口径处理。

### v2 的记录唯一性口径

- `pair_key` 是规范化后的 `A | 无向D1 | D2`，只用于三元组聚类与审计，**不再用于淘汰样本**。
- `record_key` 由规范化 A、无向 D1/D2、随 D 方向同步交换的两侧引用句、Section、Classification、参考文献及指标值稳定生成，用于记录级去重、候选唯一性和防止控制复用。D1/D2 整侧交换不改变该键。
- 只删除 `record_key` 完全相同的重复记录（exact duplicate）。同一三元组下引用句、章节或功能分类不同的记录全部保留。
- Q01 候选按块完整保留全部唯一 `record_key`；Q10/Q00 继续使用内存受控的分层候选与确定性哈希回退池。

## 严格口径核验

默认阈值为 SBERT 相似度 `0.60`、耦合强度 `10`：

| 组别 | 定义 | 预期数 |
|---|---|---:|
| Q11（ITC） | 相似度 ≥ 0.60 且耦合 ≥ 10 | 6,165 |
| Q10 | 相似度 ≥ 0.60 且耦合 < 10 | 345,230 |
| Q01 | 相似度 < 0.60 且耦合 ≥ 10 | 21,442 |
| Q00 | 相似度 < 0.60 且耦合 < 10 | 1,712,167 |

总数应为 2,085,004。四象限预期数始终按**原始行记录数**核验，而非按 `pair_key` 核验。审计同时输出原始总行数、exact duplicate 数、唯一 `record_key` 数、唯一 `pair_key` 数，以及各象限的行数/唯一记录数/唯一三元组数。相似度合法范围为 `[-1,1]`；NaN、超范围相似度或负耦合才属于数值异常，并会影响审计结论。程序还检查 6,165 条 ITC 是否全满足阈值、是否按 `record_key` 全部包含于原始数据。`01_数据口径核验.xlsx` 对每项明确写“通过/不通过”。如有任一关键项不通过，报告仍会先生成，随后自动停止，避免在错误口径上继续。

## 模型位置

程序先递归搜索数据目录下名为 `citation_sentiment_biomedbert` 且含 `config.json` 的文件夹；其次检查：

`/Users/bytedance/Desktop/1013论文数据/itc_sentiment_pipeline/models/citation_sentiment_biomedbert`

若均不存在，控制台会明确提示把此前训练好的模型文件夹复制到数据目录。程序不会重新训练或下载大型模型。设备按 CUDA → MPS → CPU 自动选择，默认 batch=16、max_length=128，并显示进度。

## 为什么这样比较

- **为什么统一模型预测**：Q11、Q10、Q01、Q00 必须使用同一测量标准，才能把组间差异解释为同一模型口径下的情感差异。程序不混用 ITC 既有人工修订标签和对照组模型标签。
- **为什么默认 1:1 匹配**：每条 Q11 在每个对照组最多选一条，避免对照数扩张造成样本膨胀，也使三次直接比较更直观。匹配优先同 A、同规范化 Section 组合、同 Classification 组合，候选不足时分层回退；情感从不参与匹配。同一 `record_key` 禁止复用，但同一 `pair_key` 下的不同记录可以分别作为控制。输出保留 `match_level`、`distance`、`record_key` 和 `pair_key`。
- **直接比较回答什么**：回答统一模型口径下，ITC 与三类非 ITC 对照在情感比例、两引用句情感一致程度及连续极性关联上相差多少。每次 Q11 vs 控制组比较都严格限于双方共同的 `match_group_id`；输出 `matched_pair_n` 和 `coverage_rate`。各组总体效应量仍按实际样本报告。

## 输出文件

- `01_数据口径核验.xlsx`
- `02_匹配样本.csv.gz`
- `03_情感预测结果.csv.gz`
- `04_ITC与非ITC直接对比结果.xlsx`
- `04_ITC与非ITC直接对比结果.json`
- `05_四组情感分布.png`
- `06_四组配对一致率.png`

统计结果包括各组句子情感分布、配对一致率、未加权 Kappa、线性加权 Kappa、Gwet AC1、Cramér V、连续极性 Spearman；Q11 分别与 Q10/Q01/Q00 比较比例差、风险比、一致率差和 Kappa 差。默认进行 1,000 次置信区间估计。卡方结果仅作辅助，解释应以效应量为主。
